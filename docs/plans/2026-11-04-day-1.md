# claude-crew Day 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A working, stack-agnostic `claude-crew`: in any git repo, a coordinator Claude Code session plans tickets, starts `scout`, `worker` and `reviewer` agents in Herdr panes, steers them, and learns results only through files, with hooks enforcing the rules.

**Architecture:** One bash script (`bin/crew`) does what text cannot do reliably: worktrees, Herdr panes, task files, journal. Roles are native Claude Code agents (`claude --agent crew-<role>`), so model, effort and tools live in agent frontmatter. Four bash hooks (guard, steer, stop-gate, board) enforce boundaries and the report contract. Three short skills carry the coordinator's judgment.

**Tech Stack:** bash 5, jq 1.7, git worktrees, Herdr 0.9, Claude Code 2.1.318. No runtime dependencies, nothing project-specific: the target repo may be any language.

**Spec:** `docs/specs/2026-11-03-claude-crew-design.md`

**Flexibility rule (from the owner):** the demo project is not known yet. Nothing in this plan may assume a language, test runner or folder layout of the target repo. Role prompts say *what good work is*, never *which command to run*.

#!/usr/bin/env bash
# Tiny assertion helpers shared by test/hooks.sh and test/crew.sh.
fails=0
pass() { echo "ok   $1"; }
fail() { echo "FAIL $1"; fails=$((fails + 1)); }
check() { local name=$1; shift; if "$@" >/dev/null 2>&1; then pass "$name"; else fail "$name"; fi; }
contains() { [[ $1 == *"$2"* ]]; }
finish() { echo "---"; echo "$fails failed"; exit $(( fails > 0 ? 1 : 0 )); }
new_repo() { # prints a fresh git repo path with one commit
  local d; d=$(mktemp -d); git -C "$d" init -q; git -C "$d" -c user.email=t@t -c user.name=t commit -q --allow-empty -m init; echo "$d"
}

- [ ] **Step 3: Write `hooks/lib.sh`**

```bash
#!/usr/bin/env bash
# Shared by bin/crew and the hooks. Needs CREW_HOME; crew_journal also needs CREW_ROOT.

# crew_journal <task-id> <event> [detail...] — append one line; the journal is never edited.
crew_journal() {
  local id=$1 event=$2; shift 2
  mkdir -p "$CREW_ROOT/.agents"
  printf '%s %s %s %s\n' "$(date -Iseconds)" "$id" "$event" "$*" >> "$CREW_ROOT/.agents/journal.log"
}

# crew_contract <role> — ERE the first line of result.md must match.
crew_contract() {
  case $1 in
    scout) echo '^ANSWER: .+' ;;
    researcher) echo '^VERDICT: .+' ;;
    judge) echo '^(DIVERGENCE|AGREE): .+' ;;
    advisor) echo '^RECOMMEND: .+' ;;
    worker) echo '^(DONE [0-9a-f]{7,40}|BLOCKED: .+)' ;;
    tester|reviewer) echo '^(PASS|FAIL) [0-9a-f]{7,40}' ;;
    docs) echo '^DOCS [0-9a-f]{7,40}' ;;
    *) return 1 ;;
  esac
}

# crew_writes <role> — success if crew.json gives the role any write globs.
crew_writes() {
  jq -e --arg r "$1" '(.write[$r] // []) | length > 0' "$CREW_HOME/crew.json" >/dev/null
}
```

- [ ] **Step 4: Write `hooks/guard.sh`**

```bash
#!/usr/bin/env bash
# PreToolUse: keep each role inside its write globs and away from shared files and dangerous git.
set -uo pipefail
[[ -n ${CREW_TASK_DIR:-} ]] || exit 0
. "$CREW_HOME/hooks/lib.sh"
input=$(cat)
tool=$(jq -r '.tool_name' <<<"$input")
id=$(basename "$CREW_TASK_DIR")

deny() {
  crew_journal "$id" blocked "$tool: $1"
  jq -n --arg r "$1" '{hookSpecificOutput:{hookEventName:"PreToolUse",permissionDecision:"deny",permissionDecisionReason:$r}}'
  exit 0
}

case $tool in
  Edit|Write|NotebookEdit)
    path=$(jq -r '.tool_input.file_path // .tool_input.notebook_path // ""' <<<"$input")
    [[ $path == "$CREW_TASK_DIR/result.md" ]] && exit 0
    [[ $path == "$CREW_WORKTREE"/* ]] || deny "Write only inside your worktree $CREW_WORKTREE, plus your report $CREW_TASK_DIR/result.md."
    rel=${path#"$CREW_WORKTREE"/}
    while IFS= read -r glob; do
      # shellcheck disable=SC2053  # glob is a pattern on purpose
      [[ $rel == $glob ]] && exit 0
    done < <(jq -r --arg r "$CREW_ROLE" '(.write[$r] // [])[]' "$CREW_HOME/crew.json")
    allowed=$(jq -r --arg r "$CREW_ROLE" '(.write[$r] // []) | join(", ")' "$CREW_HOME/crew.json")
    deny "Role $CREW_ROLE may not write $rel. Allowed: ${allowed:-nothing}. Put what you would change in your report instead."
    ;;
  Bash)
    cmd=$(jq -r '.tool_input.command // ""' <<<"$input")
    re='git[[:space:]]+(push|reset[[:space:]]+--hard|clean[[:space:]]+-[a-zA-Z]*f|branch[[:space:]]+-D|checkout[[:space:]]+(main|master)|switch[[:space:]]+(main|master))'
    [[ $cmd =~ $re ]] && deny "'${BASH_REMATCH[0]}' is not allowed for crew agents. Commit on your branch; the coordinator merges after the human agrees."
    [[ $cmd == *journal.log* ]] && deny "The journal is written only by crew."
    ;;
esac
exit 0
```

#!/usr/bin/env bash
# PostToolUse: deliver coordinator lines added to steer.md since the last delivery;
# every 25 tool calls, repeat the one default that matters (models drift back otherwise).
set -uo pipefail
[[ -n ${CREW_TASK_DIR:-} ]] || exit 0
cat >/dev/null
dir=$CREW_TASK_DIR
calls=$(( $(cat "$dir/.calls" 2>/dev/null || echo 0) + 1 ))
echo "$calls" > "$dir/.calls"
msg=""
if [[ -f $dir/steer.md ]]; then
  seen=$(cat "$dir/.steer-seen" 2>/dev/null || echo 0)
  total=$(wc -l < "$dir/steer.md")
  if (( total > seen )); then
    msg="Coordinator update (it outranks the ticket): $(tail -n +"$((seen + 1))" "$dir/steer.md")"
    echo "$total" > "$dir/.steer-seen"
  fi
fi
if (( calls % 25 == 0 )); then
  msg+="${msg:+$'\n'}Reminder: stay inside $dir/ticket.md. Verify in proportion to impact and report what you ran."
fi
[[ -n $msg ]] || exit 0
jq -n --arg c "$msg" '{hookSpecificOutput:{hookEventName:"PostToolUse",additionalContext:$c}}'

- [ ] **Step 3: Write `hooks/stop-gate.sh`**

```bash
#!/usr/bin/env bash
# Stop: an agent may finish only with a report whose first line follows its role's contract.
# Write roles also list what they ran. Accepting the report is what marks the task done.
set -uo pipefail
[[ -n ${CREW_TASK_DIR:-} ]] || exit 0
. "$CREW_HOME/hooks/lib.sh"
cat >/dev/null
dir=$CREW_TASK_DIR; id=$(basename "$dir")
[[ $(cat "$dir/status" 2>/dev/null) == running ]] || exit 0
report=$dir/result.md
re=$(crew_contract "$CREW_ROLE")
problem=""
if [[ ! -s $report ]]; then
  problem="Write your report to $report before you stop. First line must match: $re"
elif ! head -n1 "$report" | grep -Eq "$re"; then
  problem="The first line of $report must match: $re"
elif crew_writes "$CREW_ROLE" && ! grep -qi '^## Checks run' "$report"; then
  problem="Add a '## Checks run' section to $report: what you ran and what it showed."
fi
if [[ -z $problem ]]; then
  date -Iseconds > "$dir/ended"; echo done > "$dir/status"
  crew_journal "$id" done "$(head -n1 "$report")"
  exit 0
fi
strikes=$(( $(cat "$dir/.strikes" 2>/dev/null || echo 0) + 1 ))
echo "$strikes" > "$dir/.strikes"
if (( strikes >= 3 )); then
  date -Iseconds > "$dir/ended"; echo failed > "$dir/status"
  crew_journal "$id" failed "no valid report after 3 tries"
  exit 0
fi
jq -n --arg r "$problem" '{decision:"block",reason:$r}'
```

#!/usr/bin/env bash
# crew — start, steer, watch and stop Claude Code agents in Herdr panes.
# Files under .agents/ are the only channel between agents. See docs/specs/.
set -euo pipefail
CREW_HOME=${CREW_HOME:-$(cd "$(dirname "$(readlink -f "$0")")/.." && pwd)}
export CREW_HOME
HERDR=${CREW_HERDR:-herdr}
. "$CREW_HOME/hooks/lib.sh"

die() { echo "crew: $1" >&2; echo "next: $2" >&2; exit 1; }
root() { git rev-parse --show-toplevel 2>/dev/null || die "not inside a git repository" "cd into your project"; }
cfg() { jq -r "$1" "$CREW_HOME/crew.json"; }
agent_model() { sed -n 's/^model:[[:space:]]*//p' "$CREW_HOME/agents/crew-$1.md" | head -n1; }
pane_alive() { [[ -n ${1:-} ]] && "$HERDR" pane get "$1" >/dev/null 2>&1; }
task_dir() { echo "$CREW_ROOT/.agents/tasks/$1"; }

cmd_help() {
  cat <<'EOF'
crew init                                   prepare this repo (gitignore, vision/styleguide stubs, board hook)
crew spawn <id> --role R [--model M] [--branch B]   start an agent on .agents/tasks/<id>/ticket.md
crew steer <id> "text"                      correct a running agent (read after its next tool call)
crew jobs                                   table of tasks; marks dead panes failed
crew watch                                  print a line on every status change (run under Monitor)
crew stop <id>                              close the agent's pane; keep files and branch
crew log <id> <event> [detail]              append to the journal (e.g. merge)
EOF
}

cmd_init() {
  CREW_ROOT=$(root); cd "$CREW_ROOT"
  grep -qxF '.agents/' .gitignore 2>/dev/null || echo '.agents/' >> .gitignore
  [[ -f vision.md ]] || printf '# Vision\n\nWhat this product is, who it is for, where it is going.\n\n## Main modules\n' > vision.md
  [[ -f styleguide.md ]] || printf '# Styleguide\n\nRules for code here: language, naming, tests, commits, what never to do.\n' > styleguide.md
  mkdir -p .claude .agents/tasks
  local s=.claude/settings.local.json hook="$CREW_HOME/hooks/board.sh"
  [[ -f $s ]] || echo '{}' > "$s"
  jq --arg c "$hook" '
    if any(.hooks.SessionStart[]?.hooks[]?; .command == $c) then .
    else .hooks.SessionStart += [{hooks: [{type: "command", command: $c}]}] end' "$s" > "$s.tmp"
  mv "$s.tmp" "$s"
  echo "crew ready in $CREW_ROOT"
  echo "next: shape vision.md and styleguide.md with the agent (10-30 lines each)"
}

cmd_spawn() {
  local id=${1:-} role="" model="" branch=""
  [[ -n $id ]] || die "missing task id" "crew spawn T01-slug --role worker"
  shift
  while (( $# )); do
    case $1 in
      --role) role=${2:-}; shift 2 ;;
      --model) model=${2:-}; shift 2 ;;
      --branch) branch=${2:-}; shift 2 ;;
      *) die "unknown option $1" "crew help" ;;
    esac
  done
  [[ -n $role ]] || die "missing --role" "add --role worker (or scout, reviewer, ...)"
  [[ -f $CREW_HOME/agents/crew-$role.md ]] || die "no agent crew-$role" "add $CREW_HOME/agents/crew-$role.md"
  CREW_ROOT=$(root); export CREW_ROOT
  local dir; dir=$(task_dir "$id")
  [[ -f $dir/ticket.md ]] || die "no ticket at $dir/ticket.md" "write the ticket first (crew-plan)"
  local st; st=$(cat "$dir/status" 2>/dev/null || echo queued)
  [[ $st == running || $st == done ]] && die "$id is already $st" "crew jobs"
  local running max
  running=$( (grep -lx running "$CREW_ROOT"/.agents/tasks/*/status 2>/dev/null || true) | wc -l)
  max=$(cfg .max_parallel)
  (( running < max )) || die "limit of $max running agents reached" "wait for a running task (crew jobs)"

  # A new run starts clean; the previous report is kept for the coordinator.
  [[ -f $dir/result.md ]] && mv "$dir/result.md" "$dir/result.prev.md"
  rm -f "$dir/.strikes" "$dir/.calls" "$dir/.steer-seen" "$dir/ended"

  local wt=$CREW_ROOT/.agents/worktrees/$id
  if [[ ! -d $wt ]]; then
    if crew_writes "$role"; then
      branch=${branch:-crew/$id}
      if git -C "$CREW_ROOT" show-ref --verify --quiet "refs/heads/$branch"; then
        git -C "$CREW_ROOT" worktree add -q "$wt" "$branch"
      else
        git -C "$CREW_ROOT" worktree add -q -b "$branch" "$wt"
      fi
    else
      git -C "$CREW_ROOT" worktree add -q --detach "$wt" "${branch:-HEAD}"
    fi
  fi

  local anchor=(--current --direction right) last out pane
  last=$(cat "$CREW_ROOT/.agents/last-pane" 2>/dev/null || true)
  pane_alive "$last" && anchor=("$last" --direction down)
  out=$("$HERDR" pane split "${anchor[@]}" --cwd "$wt" --no-focus \
        --env "CREW_ROOT=$CREW_ROOT" --env "CREW_TASK_DIR=$dir" --env "CREW_ROLE=$role" \
        --env "CREW_WORKTREE=$wt" --env "CREW_HOME=$CREW_HOME") \
    || die "herdr could not open a pane" "run crew from a pane inside Herdr"
  pane=$(jq -r '.result.pane.pane_id' <<<"$out")
  echo "$pane" > "$CREW_ROOT/.agents/last-pane"

  local name args
  name=$(tr 'A-Z' 'a-z' <<<"$id" | tr -c 'a-z0-9_\n-' '-' | cut -c1-32)
  args=(--agent "crew-$role" --permission-mode "$(cfg .permission_mode)" --settings "$CREW_HOME/hooks/worker.json")
  [[ -n $model ]] && args+=(--model "$model")
  "$HERDR" agent start "$name" --kind claude --pane "$pane" --timeout 60000 -- "${args[@]}" >/dev/null \
    || die "the agent did not start in pane $pane" "look at pane $pane (e.g. accept the folder-trust dialog), then crew spawn $id --role $role again"

  echo "$role" > "$dir/role"; echo "${model:-$(agent_model "$role")}" > "$dir/model"
  echo "$branch" > "$dir/branch"; echo "$pane" > "$dir/pane"
  date -Iseconds > "$dir/started"; echo running > "$dir/status"
  crew_journal "$id" spawn "role=$role model=$(cat "$dir/model") pane=$pane branch=${branch:--}"

  local first="You are on crew task $id. Ticket: $dir/ticket.md. Read $CREW_ROOT/vision.md and $CREW_ROOT/styleguide.md first."
  [[ -n $branch ]] && first+=" Branch: $branch."
  [[ $role == reviewer && -f $CREW_ROOT/CODING_STANDARDS.md ]] && first+=" Coding standards: $CREW_ROOT/CODING_STANDARDS.md."
  first+=" When you finish, write your report to $dir/result.md."
  "$HERDR" agent prompt "$name" "$first" >/dev/null

  echo "started $id ($role, $(cat "$dir/model")) in pane $pane"
  echo "next: crew watch reports when $dir/status changes"
}

main() {
  local cmd=${1:-help}; shift || true
  case $cmd in
    init) cmd_init "$@" ;;
    spawn) cmd_spawn "$@" ;;
    help|-h|--help) cmd_help ;;
    *) die "unknown command $cmd" "crew help" ;;
  esac
}
main "$@"

```bash
cmd_steer() {
  local id=${1:-} text=${2:-}
  [[ -n $id && -n $text ]] || die "usage: crew steer <id> \"text\"" "crew steer T01-slug \"stay on the failing test\""
  CREW_ROOT=$(root); export CREW_ROOT
  local dir; dir=$(task_dir "$id")
  [[ $(cat "$dir/status" 2>/dev/null) == running ]] || die "$id is not running" "crew jobs"
  printf '%s\n' "$text" >> "$dir/steer.md"
  crew_journal "$id" steer "$text"
  echo "steered $id"
  echo "next: the agent reads it after its next tool call"
}

cmd_jobs() {
  CREW_ROOT=$(root); export CREW_ROOT
  local fmt='%-26s %-9s %-7s %-8s %4s  %s\n' now any=0 dir id st min end
  now=$(date +%s)
  printf "$fmt" TASK ROLE MODEL STATUS MIN RESULT
  for dir in "$CREW_ROOT"/.agents/tasks/*/; do
    [[ -f $dir/ticket.md ]] || continue
    any=1; id=$(basename "$dir"); st=$(cat "$dir/status" 2>/dev/null || echo queued)
    if [[ $st == running ]] && ! pane_alive "$(cat "$dir/pane" 2>/dev/null)"; then
      st=failed; echo failed > "$dir/status"; date -Iseconds > "$dir/ended"
      crew_journal "$id" failed "pane closed while running"
    fi
    min=-
    if [[ -f $dir/started ]]; then
      end=$now; [[ -f $dir/ended ]] && end=$(date -d "$(cat "$dir/ended")" +%s)
      min=$(( (end - $(date -d "$(cat "$dir/started")" +%s)) / 60 ))
    fi
    printf "$fmt" "$id" "$(cat "$dir/role" 2>/dev/null || echo -)" "$(cat "$dir/model" 2>/dev/null || echo -)" \
      "$st" "$min" "$(head -n1 "$dir/result.md" 2>/dev/null | cut -c1-60)"
  done
  if (( ! any )); then echo "next: no tasks yet; plan them with crew-plan"
  elif grep -qx done "$CREW_ROOT"/.agents/tasks/*/status 2>/dev/null; then echo "next: review or merge done tasks; crew stop <id> closes their panes"
  else echo "next: wait for running tasks (crew watch)"; fi
}

cmd_watch() {
  CREW_ROOT=$(root)
  declare -A seen=()
  local f id st
  while :; do
    for f in "$CREW_ROOT"/.agents/tasks/*/status; do
      [[ -f $f ]] || continue
      id=$(basename "$(dirname "$f")"); st=$(cat "$f")
      if [[ ${seen[$id]+x} && ${seen[$id]} != "$st" ]]; then
        echo "$id $st $(head -n1 "$(dirname "$f")/result.md" 2>/dev/null)"
      fi
      seen[$id]=$st
    done
    sleep "${CREW_WATCH_INTERVAL:-5}"
  done
}

cmd_stop() {
  local id=${1:-}; [[ -n $id ]] || die "missing task id" "crew stop T01-slug"
  CREW_ROOT=$(root); export CREW_ROOT
  local dir role; dir=$(task_dir "$id")
  [[ -d $dir ]] || die "no task $id" "crew jobs"
  "$HERDR" pane close "$(cat "$dir/pane" 2>/dev/null)" >/dev/null 2>&1 || true
  if [[ $(cat "$dir/status" 2>/dev/null) == running ]]; then
    echo failed > "$dir/status"; date -Iseconds > "$dir/ended"
  fi
  role=$(cat "$dir/role" 2>/dev/null || true)
  if [[ -n $role ]] && ! crew_writes "$role"; then
    git -C "$CREW_ROOT" worktree remove --force "$CREW_ROOT/.agents/worktrees/$id" 2>/dev/null || true
  fi
  crew_journal "$id" stop "pane closed"
  echo "stopped $id"
  echo "next: crew jobs"
}

cmd_log() {
  (( $# >= 2 )) || die "usage: crew log <id> <event> [detail]" "crew log T01-slug merge abc1234"
  CREW_ROOT=$(root); export CREW_ROOT
  crew_journal "$@"
  echo "logged $1 $2"
  echo "next: crew jobs"
}

# crew

You coordinate; agents do the work. Each agent runs in its own Herdr pane and git worktree, as a native Claude Code agent (`crew-<role>`) with the model its role needs. Agents never talk to each other or to you directly: tickets, reports and the journal under `.agents/` are the only channel. Hooks enforce the boundaries; you supply judgment.

- New goal → load the `crew-plan` skill.
- Tickets exist and are approved → load the `crew-run` skill.
- "What is going on?" → run `crew jobs`, then read the reports it points to.
- First time in this repo → `crew init`, then shape `vision.md` and `styleguide.md` with the human (10–30 lines each).

`crew help` lists the commands. Every command ends with a `next:` line; follow it unless you have a reason not to.
```

# crew-plan

Tickets that one agent can finish in one fresh context are the whole trick: short threads stay sharp.

1. Understand the goal. If the repository or the area is unfamiliar, write one scout ticket (`T00-scout-<topic>`, holding one question), run `crew spawn T00-scout-<topic> --role scout`, and read its report when `crew watch` shows it done.
2. Draft tracer-bullet vertical slices, as the `to-tickets` skill defines them: each slice is a narrow but complete path through every layer, verifiable on its own, and small enough for one fresh context. Prefactoring comes first.
3. Give each ticket its blocking edges. Number tickets `T01`, `T02`, … in dependency order; the id is `T<NN>-<short-slug>`.
4. Show the human a numbered list: id, title, role (worker unless there is a reason), blocked by, what it delivers. Ask whether the granularity and the edges are right. Iterate until they approve.
5. Only after approval, write `.agents/tasks/<id>/ticket.md` for each ticket from the template below and `queued` into `.agents/tasks/<id>/status`.

You are done when the human has approved the list and every ticket file exists. Then load `crew-run`.

Ticket template:

    # T01: <title>

    **What to build:** <the end-to-end behaviour, from the user's side>

    **Blocked by:** None (can start immediately)   | T0x

    - [ ] <acceptance criterion a reviewer can check>
    - [ ] <acceptance criterion a reviewer can check>
```

- [ ] **Step 3: Write `skills/crew-run/SKILL.md`**

name: crew-run
description: Run approved crew tickets — spawn the frontier, watch status, steer, review, and merge only with the human's yes. Use after crew-plan, or when the user asks crew to continue.
---

# crew-run

Keep your own context small: refer to tasks by path, read reports when they arrive, never paste files into prompts.

1. Start the watcher once: run `crew watch` with the Monitor tool. Each line it prints is a wake-up: `<id> <status> <first line of the report>`.
2. Spawn the frontier: every `queued` ticket whose blockers are all `done` and merged, with `crew spawn <id> --role <role>`. `crew` refuses past the parallel limit; the rest waits.
3. While agents work, stay available to the human. To correct an agent, `crew steer <id> "<one clear instruction>"`.
4. On a worker's `done`: read its `result.md`. `BLOCKED:` → tell the human. `DONE <sha>` → write a review ticket `.agents/tasks/<id>-review/ticket.md` that points to the worker's ticket, then `crew spawn <id>-review --role reviewer --branch crew/<id>`.
5. On the reviewer's report: `PASS` → show the human the reviewer's summary and `git diff --stat main...crew/<id>`, and ask to merge. Merge only on a clear yes, with `git merge --no-ff crew/<id>`, then `crew log <id> merge <sha>`. `FAIL` → one repair: `crew steer` is not enough once a worker is done, so write the reviewer's "For the coordinator" list into the worker's ticket under `## Repair 1` and `crew spawn <id> --role worker` again. A second `FAIL` goes to the human.
6. `crew stop <id>` every pane whose task is done or failed, so the screen and the usage limit stay clean. After a merge, `git worktree remove .agents/worktrees/<id>`.
7. A `failed` task: read its report and the journal tail, tell the human what happened and propose one next step. Never switch a model silently.

You are done when every ticket is merged, or waiting on a decision only the human can make.
```

Note for step 5: a repair re-spawns a `done` task, which `crew spawn` refuses. Set the worker task's status back with `echo queued > .agents/tasks/<id>/status` before re-spawning, and include that line in the skill's step 5 text:

#!/usr/bin/env bash
# Links crew's skills, agents and CLI into your Claude Code and PATH. Safe to run again.
set -euo pipefail
here=$(cd "$(dirname "$0")" && pwd)
mkdir -p ~/.claude/skills ~/.claude/agents ~/.local/bin
link() {
  if [[ -e $2 && ! -L $2 ]]; then echo "skip $2 (exists and is not a link)"; return; fi
  ln -sfn "$1" "$2"; echo "link $2"
}
for d in "$here"/skills/*/; do link "${d%/}" ~/.claude/skills/"$(basename "$d")"; done
for f in "$here"/agents/*.md; do link "$f" ~/.claude/agents/"$(basename "$f")"; done
link "$here/bin/crew" ~/.local/bin/crew
chmod +x "$here"/bin/crew "$here"/hooks/*.sh
command -v jq >/dev/null || echo "warning: jq is required"
command -v herdr >/dev/null || echo "warning: herdr is required"
echo "next: open your project in a Herdr pane, run 'crew init', then start claude and say: use crew"

# How I work with agents

One page. The same five steps whatever we build.

1. **Context first.** `vision.md` and `styleguide.md`, 10–30 lines each, written with the agent. Every agent reads them first. Long files get ignored, so they stay short.
2. **Plan into small tickets.** The coordinator splits the goal into tracer-bullet slices with "Blocked by" edges, each small enough for one fresh context. I approve the list before anything runs.
3. **Right agent, right model.** Each ticket runs as a native Claude Code agent in its own pane and git worktree: scout on Haiku, worker on Sonnet, reviewer on Opus. One subscription, so cheap by default and a parallel limit.
4. **Rules in code, judgment in text.** Hooks enforce what must always hold: where a role may write, no push, no finish without a report that shows what was run. Skills and role prompts carry principles with their reasons.
5. **Trust is earned.** A reviewer checks Spec and Standards and labels findings proven, plausible or unverified. Only a proven break fails. I merge, after reading the review. The journal records every step, so a retro can improve the setup.

What went wrong and what it changed:
- Two helper agents started on the default model burned 98% of my usage limit and then sat idle → model per role, a parallel limit, panes closed when done.
- An email agent's model refused a legitimate follow-up, and a stranger joined the thread → a fallback model, a sender check in code, and replaying a failure offline before fixing it.
